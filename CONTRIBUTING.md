# Contributing to Mündig

Mündig is research-stage. The substance is in [`docs/`](docs/); there is no code yet. This file sets expectations about what kinds of engagement are most useful and what kinds won't land.

## Most useful contributions

- **Citation corrections and fact-checks.** The docs make philosophical claims and the research is AI-assisted (see [`docs/ai-assisted-research.md`](docs/ai-assisted-research.md)). Misattributions, fabricated quotes, weak section references — all flag-worthy. The project's standard requires every philosophical claim to be sourced; help us hold to it.
- **Pointers to literature that complicates or contests claims.** "X argues Y, here is why it cuts against the doc's framing" lands much harder than "X is wrong." The project does not claim philosophical authority; it claims to be doing its work in public so better-read readers can sharpen it.
- **Philosophical pushback that engages with the project's framework.** Particularly: critiques of the techno-feudal framing, of the Habermasian framing, or of how the two have been combined. The framework is not load-bearing because Mündig says so; it is load-bearing because it survives engagement.
- **Design alternatives that engage with the two tests.** A proposal that explicitly states how it fares against the techno-feudal and Habermasian tests (see [`README.md`](README.md)) is welcome even if it diverges from the current sketch. A proposal that does not engage with the tests is not yet a Mündig proposal.
- **Typo fixes, link fixes, formatting cleanups.** Low-friction, always welcome.

## What won't land

- **Off-topic grievances against named platforms.** The critique is structural, not directed at named adversaries. "Platform X did Y" is rarely useful unless it sharpens a structural claim already in the docs.
- **Feature requests and scope demands.** The project's scope is deliberately open ([`docs/techno-feudalism/habermas/deliberative-social-app/open-questions.md`](docs/techno-feudalism/habermas/deliberative-social-app/open-questions.md)); "build X" requests will not land until the scope question is resolved enough to make sense of them.
- **AI-generated bulk PRs.** Drive-by AI contributions that show no evidence of human judgement will be closed without merge. The project is itself AI-assisted, which is exactly why it knows the failure modes; the standard set in [`docs/ai-assisted-research.md`](docs/ai-assisted-research.md) applies to contributions too.

## How to engage

- **Discussions** for open-ended philosophical questions, scope conversations, or anything that isn't yet sharp enough to be an issue.
- **Issues** for citation corrections, factual challenges, pointers to literature, design alternatives, specific scope questions.
- **Pull requests** for typo / link / formatting fixes, or for substantive doc edits that have been discussed in an issue or discussion first.

## On tone

The project's deliberative norms apply to its own engagement: communicative action (orientation toward mutual understanding) over strategic action (orientation toward winning). Issues and PRs that show the same standard the docs aim at will get the most thoughtful response.

## Legal note on contributions

No licence has yet been granted to any portion of this repository (see [`README.md`](README.md) and [`docs/licensing.md`](docs/licensing.md) for the per-component-deferred approach). By submitting a contribution, you assert that you have the right to contribute it and you grant permission for it to be incorporated under whatever licence is eventually applied to the affected component. A more formal contributor agreement may be added later if the project's posture warrants it.
